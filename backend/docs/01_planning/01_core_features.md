# 01. Core Features

## 프로젝트 개요

이 서비스는 TV·YouTube 여행 콘텐츠에서 발견한 장소를 실제 여행으로 연결하고,
사용자 및 동행자의 조건을 반영해 실행 가능한 자유여행 일정을 생성하는 AI 여행 서비스다.

또한 여행 현장에서는 사진을 촬영해 장소를 추정하고 설명을 제공하는
스마트 도슨트 기능을 제공한다.

---

# 핵심 설계 원칙

- AI는 해석하고, 시스템은 검증한다.
- 사용자에게 긴 프롬프트 작성을 요구하지 않는다.
- 사용자와 동행자의 취향 및 이동 조건을 여행계획에 반영한다.
- AI가 생성한 일정은 최종 정답이 아니라 수정 가능한 초안이다.
- 사진 기반 장소 인식은 확정 표현을 사용하지 않는다.
- 확인되지 않은 실제 정보는 AI가 임의로 생성하지 않는다.
- 여행 전 기능과 여행 중 기능을 구분한다.

---

# 주요 기능 7개

## 1. 사용자·동행자 관리

사용자의 기본 여행 성향과 함께 여행하는 동행자의 특성을 저장하고 관리한다.

### 사용자 기본 정보

- 닉네임
- 연령대

### 사용자 여행 성향

- 관심 여행 유형
  - 자연
  - 음식
  - 카페
  - 문화
  - 역사
  - 쇼핑
  - 전시
  - 체험 등
- 걷기 허용 정도
- 휴식 빈도
- 계단 회피 여부
- 언덕 회피 여부
- 택시 이용 가능 여부

### 동행자 정보

- 이름 또는 별명
- 관계
- 연령대
- 여행 관심사
- 걷기 허용 정도
- 휴식 빈도
- 계단 회피 여부
- 언덕 회피 여부
- 택시 이용 가능 여부

동행자 정보는 여행 생성 시 선택해 반영할 수 있다.

## 2. 여행계획 입력·취향 분석

사용자가 이번 여행에 필요한 조건을 입력하고,
YouTube 콘텐츠 정보 등을 함께 활용해 이번 여행의 관심사와 취향을 분석한다.

### 여행 입력 조건

- 출발지
- 여행 목적지
- 여행 시작일
- 여행 종료일
- 기간
- 예산
- 이동수단
- 동행자
- 이번 여행의 추가 이동 조건

### YouTube 콘텐츠 활용

YouTube 콘텐츠는 별도의 독립 기능이 아니라
AI 여행계획을 위한 입력 데이터 중 하나로 사용한다.

활용 데이터:

- title
- description
- tags
- videoId
- channelId

활용 목적:

- 관심 지역 추정
- 관심 장소 후보 파악
- 여행 취향 추정
- 여행 일정 생성 시 참고

YouTube 메타데이터만으로 장면을 정확히 인식했다고 표현하지 않는다.

---

## 3. 여행 데이터 수집·검증

AI 여행계획에 필요한 실제 정보를 외부 API에서 가져오고 검증한다.

### 수집 대상

- 장소 정보
- 관광지 정보
- 주소
- 좌표
- 운영정보
- 이동정보
- 날씨
- 기타 일정 생성에 필요한 실제 데이터

### 역할 구분

#### Kakao Map

- 장소 검색
- 주소
- 좌표
- 장소 존재 여부 확인

#### TourAPI

- 관광지 상세정보
- 관광 콘텐츠
- 관광 관련 운영정보

#### 기상청 API

- 여행 날짜의 날씨 정보
- 날씨 기반 일정 변경 조건

이 기능은 주로 FastAPI 내부 Service로 동작하며,
Flutter가 외부 API를 직접 호출하는 구조를 기본으로 하지 않는다.

---

## 4. AI 여행 일정 생성

사용자와 동행자의 조건,
콘텐츠 기반 취향,
관광 데이터 등을 결합해 여행 일정 초안을 생성한다.

### 입력

- 사용자 여행 성향
- 동행자 여행 성향
- 이번 여행 조건
- 콘텐츠 기반 관심사
- 장소 및 관광정보
- 이동 관련 정보
- 날씨

### AI 역할

EXAONE을 중심으로 다음 역할을 수행한다.

- 사용자 조건 해석
- 동행자 조건 해석
- 여행 관심사 반영
- 일정 초안 생성
- 일정 구성 이유 설명

### 출력

예:

- Day 1
  - 10:00 경복궁
  - 12:00 점심
  - 14:00 국립민속박물관
  - 16:00 카페

AI가 생성한 결과는 최종 확정 일정이 아니라 초안이다.

---

## 5. 여행 일정 검증

AI가 만든 일정을 실제 데이터 기준으로 검증한다.

### 검증 항목

- 실제 장소 존재 여부
- 좌표
- 운영시간
- 이동시간
- 일정 간 시간 충돌
- 날짜 오류
- 이동 가능성
- 날씨 조건
- 사용자 걷기 조건
- 사용자 휴식 조건
- 동행자 이동 조건

### 핵심 원칙

AI가 검증 결과를 생성하지 않는다.

백엔드 코드와 외부 API가 실제 정보를 검증한다.

일정 생성, 수정, 재구성 후 자동으로 검증을 수행한다.

---

## 6. 일정 수정·재구성·저장

사용자는 AI가 만든 일정 초안을 직접 수정할 수 있다.

### 직접 수정

- 장소 삭제
- 장소 교체
- 장소 추가
- 순서 변경
- 휴식 추가
- 일정 시간 수정

### AI 재구성

상황 변화에 따라 일정을 다시 만들 수 있다.

예:

- "많이 걸어서 힘들어요."
- "비가 와요."
- "야외 일정 대신 실내로 바꿔주세요."
- "택시를 이용할게요."
- "이 장소는 빼주세요."

### 처리 흐름

현재 일정
→ 사용자 변경 요청
→ EXAONE 재구성
→ Backend Validation
→ 수정 일정 저장

### 저장

- 생성된 일정은 DB에 저장
- 수정된 일정은 자동 저장
- 변경 이력은 별도 Revision으로 관리
- 사용자가 최종 일정으로 확정 가능

## 7. 스마트 도슨트

스마트 도슨트는 AI 여행계획과 별개의 여행 현장 기능이다.

### 목적

사용자가 여행 중 눈앞에 있는 장소의 사진을 찍으면
장소 후보를 추정하고,
사용자가 선택한 장소를 AI가 설명한다.

### 처리 흐름

사용자 사진 촬영
→ Gemini 이미지 분석
→ 장소 후보 추정
→ 실제 장소 후보 검증
→ 사용자에게 후보 제공
→ 사용자 선택
→ EXAONE 장소 설명

### Gemini 역할

- 이미지 분석
- 장소 후보 추정

결과를 확정적으로 표현하지 않는다.

예:

- "경복궁일 가능성이 있습니다."
- "이곳은 경복궁이 아닐까요?"
- "아래 장소 중 하나로 보입니다."

정확한 장소를 특정하기 어려운 경우 이를 그대로 알린다.

### EXAONE 역할

사용자가 선택한 장소에 대해 다음 정보를 설명한다.

- 장소 소개
- 역사 및 문화적 특징
- 주요 볼거리
- 여행자가 알아두면 좋은 정보
- 시니어도 이해하기 쉬운 설명

EXAONE에는 검증된 장소 데이터를 함께 제공하며,
장소에 대한 사실을 자유롭게 만들어내도록 하지 않는다.

→ 사진 촬영
→ Gemini 장소 후보 추정
→ 사용자 확인
→ EXAONE 스마트 도슨트 설명

# Codex 구현 시 고정 원칙

1. 로그인은 핵심 기능 7개와 별도의 공통 기반 기능으로 구현한다.
2. user_id를 Request Body로 받아 현재 사용자를 판단하지 않는다.
3. 로그인 JWT를 통해 현재 사용자를 식별한다.
4. YouTube 메타데이터는 여행계획의 입력 데이터다.
5. 스마트 도슨트와 YouTube 취향 분석을 같은 기능으로 구현하지 않는다.
6. Gemini의 장소 추정 결과는 확정값으로 사용자에게 보여주지 않는다.
7. 스마트 도슨트 설명은 사용자가 장소 후보를 선택한 후 생성한다.
8. EXAONE은 일정 초안을 생성하며 실제 운영정보를 확정하지 않는다.
9. 실제 장소, 시간, 날씨 등은 Backend와 외부 API가 검증한다.
10. 외부 API 장애 시 AI가 실제 정보를 추측해 채우지 않는다.
