# 여행메이트 디자인 설계서

작성일: 2026-09-21  
버전: 목업 기준 v1.0

## 1. 제품 정의

여행메이트는 사용자의 취향, 동행자 조건, 날짜, 이동수단, 예산을 바탕으로 여행을 계획하고, 여행 중에는 일정과 길찾기를 빠르게 확인하도록 돕는 모바일 우선 서비스다.

### 핵심 과업

1. 관심 장소를 찾거나 저장한 장소에서 여행을 시작한다.
2. 장소, 날짜, 인원, 이동수단, 예산, 동행자 조건을 입력해 일정을 만든다.
3. 생성된 일정의 부담도를 확인·조정하고 숙소를 정한다.
4. 여행 당일 다음 일정과 길찾기를 빠르게 실행한다.
5. 시니어에게는 접근 편의성과 사용성이 보장된 설계가 이뤄져야하고, 일반 이용자에게는 사용자 친화적인 UI로 화면 구현이 이뤄져야 한다. 
### 경험 원칙

- 한 화면에서 사용자가 내려야 할 주된 결정은 하나로 제한한다.
- AI 추천에는 근거, 수정 수단, 실패 시 대안을 제공한다.
- 동행자 조건은 일정 난이도와 현장 안내에 반영한다.
- 당일 화면은 다음 행동, 시간, 이동 정보를 우선한다.
- 되돌리기와 수정은 언제나 가능하게 한다.

## 2. 정보 구조

| 영역 | 화면 | 주요 행동 |
| --- | --- | --- |
| 시작 | 로그인, 회원가입, 취향 설정 | 로그인, 가입, 취향 저장 |
| 홈 | 홈, 알림, 프로필 | 여행 만들기, 검색, 일정 보기 |
| 탐색 | 음성/사진 검색, 분석, 결과, 저장 장소, 상세, 지도 | 장소 탐색, 평가, 여행에 추가 |
| 계획 | 장소, 날짜, 인원, 교통, 예산, 동행자, 확인 | 조건 입력, 일정 생성 |
| 여행 | 일정, 숙소, 출발 전, 오늘의 여행, 길찾기 | 일정 조정, 숙소 확정, 길찾기 |
| 기록 | 지난 여행 | 다시 보기, 재계획 |

```text
홈 → 여행 만들기 → 장소 → 날짜 → 인원 → 이동수단 → 예산 → 동행자
   → 조건 확인 → AI 일정 생성 → 일정 검토 → 숙소 → 출발 전 → 오늘의 여행 → 길찾기
```

보조 흐름은 `홈 → 검색/사진/저장 장소 → 장소 상세 → 여행 만들기`로 합류한다. 이전 선택은 보존하고 확정 전 수정할 수 있어야 한다.

## 3. 앱 셸과 반응형

### 기준

- 현재 목업 프레임은 384×844px 세로 모바일 뷰다.
- `상단 safe area → 헤더 → 스크롤 콘텐츠 → action bar → 조건부 BottomNav` 순서로 구성한다.
- BottomNav는 홈, 지도, 저장, 마이 영역에서만 노출한다.

### 구현 규칙

```text
AppShell (min-height: 100dvh)
├─ Status / safe-area
├─ Page header (선택)
├─ Scrollable content (flex: 1; min-height: 0)
├─ Action bar (선택, shell 내부 sticky)
└─ Bottom navigation (선택)
```

- 화면 내부 CTA는 브라우저 뷰포트에 `fixed`하지 않는다.
- 360–479px: 기본 좌우 여백 20px.
- 480–767px: 콘텐츠 폭 480px 이하, 여백 확대.
- 768px 이상 실제 웹: 과업에 따라 중앙 단일 열 또는 주 콘텐츠+보조 정보 2열을 사용한다.
- 배포 환경에서는 action bar와 BottomNav에 `env(safe-area-inset-*)`를 적용한다.

## 6. 화면 설계 규칙

### 홈

- 첫 카드에는 ‘현재/다가오는 여행’ 또는 ‘여행 만들기’ 중 하나만 주 행동으로 둔다.
- 검색은 텍스트, 음성, 사진의 목적을 구분한다.
- 저장 장소와 지난 여행은 보조 섹션으로 배치한다.
- 알림 배지는 숫자 또는 요약을 제공하며 점만으로 정보를 전달하지 않는다.

### 여행 생성

- 헤더에 현재 단계와 진행률을 표시한다.
- 선택값은 이전/다음 이동 시 보존한다.
- 비활성 다음 버튼에는 필요한 조건과 해결 방법을 설명한다.
- 동행자 조건은 개인/전체 조건을 구분하며, 삭제·변경은 복구 가능하게 한다.

### AI 일정과 검토

- 생성 중에는 예상 시간, 취소/뒤로가기 가능 여부, 대안을 제공한다.
- 추천 결과는 취향, 이동 시간, 예산, 동행자 조건 중 어떤 근거가 반영됐는지 보여준다.
- ‘일정이 힘들어요’는 이동·계단·대기·시간대 등을 수집해 수정 전후를 비교한다.

### 여행 당일과 길찾기

- 첫 정보는 다음 목적지, 마감 시간, 소요 시간이다.
- 위치 권한 전/허용/거부, 오프라인, 경로 없음, 재탐색 상태를 설계한다.
- 지도 이미지는 목업 배경일 뿐이며, 실제 기능에는 지도 공급자·출처·대체 전략이 필요하다.

| --- | --- | --- | --- | --- |

| 사진 분석 | 처리 단계·예상 시간 | 해당 없음 | 지원 불가 사진/권한 거부 | 인식 장소, 신뢰도, 수정 |
| AI 일정 | 조건 요약·진행 | 생성 불가 조건 | 재시도/수동 일정 | 추천 근거, 수정 진입 |

## 8. 접근성·콘텐츠·모션

- 아이콘 버튼은 `알림 열기`, `이전 화면으로`, `장소 저장`, `시트 닫기`처럼 구체적 이름을 제공한다.
- `:focus-visible`은 primary 기반의 고대비 ring으로 통일한다.
- 선택 UI는 native radio/checkbox를 우선하고, 커스텀 UI는 선택 상태를 프로그램적으로 전달한다.
- 모달을 열면 첫 유효 컨트롤로 포커스를 이동하고, 닫으면 호출 요소로 되돌린다.
- 오류는 원인 → 영향 → 다음 행동 순으로 쓴다.
- 모션 기본값은 150–250ms이며 `prefers-reduced-motion`에서 scale/전환을 줄인다.
- 시니어 모드는 폰트뿐 아니라 행간, 버튼 높이, 정보 밀도, 대비를 함께 조정한다.

## 9. 검증 체크리스트

- [ ] 360px, 390px, 1024px 이상에서 주요 화면을 확인했다.
- [ ] header/content/action bar/BottomNav가 서로 가리지 않는다.
- [ ] 키보드만으로 여행 생성 및 바텀시트를 조작한다.
- [ ] 입력·선택·이미지·아이콘에 적절한 접근성 정보를 제공한다.
- [ ] 핵심 기능마다 로딩·빈·오류·성공 상태를 확인한다.
- [ ] 장문 장소명, 날짜, 금액, 동행자 이름에도 overflow가 없다.
- [ ] production build와 브라우저 검증을 통과한다.

## 11. 시니어 전용 페이지: 편안한 여행

### 목적과 범위

`편안한 여행`은 시니어 모드의 설정 화면이 아니라, 여행 중 다음 행동을 빠르고 확실하게 실행하는 독립 목적지다. 사용자가 긴 목록을 탐색하거나 작은 컨트롤을 해석하지 않고도 **지금 할 일**, **어디로 가는지**, **도움이 필요한지**를 판단하게 한다.

초기 범위는 여행 당일로 제한한다. 건강 정보, 보호자 위치 공유, 긴급 연락처는 민감 정보·동의·운영 정책이 확정되기 전에는 구현하지 않는다.

### 진입과 종료

- 홈의 현재/다가오는 여행 카드에 `편안한 여행으로 보기` 보조 CTA를 제공한다.
- 프로필의 시니어 모드 설명에서 미리보기/진입을 제공한다.
- 화면 상단에는 `일반 화면으로 보기`를 제공하되, 현재 여행과 선택값은 유지한다.
- BottomNav는 기존 구조를 유지하며 이 페이지는 홈 맥락의 하위 화면으로 취급한다.

### 화면 구조

```text
PageHeader: 편안한 여행 / 일반 화면으로 보기
├─ 상태 요약: 오늘 n일차 · 현재 시간 · 여행 상태
├─ 다음 행동 카드 (최우선)
│  ├─ 장소명, 예정 시각, 남은 시간, 이동 방법
│  └─ [길찾기 시작] Primary
├─ 오늘의 일정 (최대 3개, 시간순)
│  └─ 각 항목: 장소 · 시간 · 이동/휴식 정보 · 상세 보기
├─ 빠른 도움
│  ├─ [일정 다시 보기] [목적지 검색]
│  └─ [도움이 필요해요] Secondary
└─ 여행 설정
   └─ 글자 크기 · 고대비 · 안내 속도/모션
```

### 정보 위계와 콘텐츠 규칙

- 최상단에는 한 개의 `다음 행동 카드`만 둔다. 보조 기능이 길찾기보다 눈에 띄면 안 된다.
- 시간은 ‘13:00’만 표시하지 않고 `13:00 · 25분 후`처럼 절대·상대 시간을 함께 제공한다.
- 이동 정보는 `도보 8분`, `택시 약 12분`처럼 행동과 예상 소요를 명확히 쓴다.
- 일정은 첫 화면에서 최대 3개만 보이고, 나머지는 `오늘 일정 모두 보기`로 점진 공개한다.
- 상태 색상에는 항상 텍스트와 아이콘을 같이 쓴다. 예: `휴식 권장`, `다음 장소까지 8분`.
- 용어는 `경로 탐색`보다 `길찾기`, `접근성 설정`보다 `화면을 더 편하게 보기`처럼 행동 중심으로 쓴다.

### 컴포넌트·인터랙션 명세

| 요소 | 규칙 |
| --- | --- |
| 다음 행동 카드 | 화면 진입 시 첫 번째 콘텐츠. 다음 목적지가 없으면 ‘다음 일정이 없어요’와 일정 전체 보기 CTA를 제공한다. |
| 길찾기 시작 | 가장 큰 primary 버튼. 위치 권한 전/허용/거부, 네트워크 오류, 경로 없음 상태를 제공한다. |
| 오늘의 일정 | 카드 전체가 조작 대상이 되지 않도록 상세 행동을 명확히 라벨링한다. 휴식·이동 시간이 긴 항목은 텍스트로 강조한다. |
| 도움 필요 | 즉시 외부 연락을 실행하지 않는다. 먼저 ‘무엇이 불편한가요?’ 선택지와 취소 가능한 다음 행동을 제공한다. |
| 화면 편의 설정 | 글자 크기, 고대비, 모션 감소를 독립 토글로 제공하고 즉시 반영·저장 여부를 안내한다. |

### 접근성 기준

- 기본 본문은 18px 이상, 핵심 제목은 24px 이상, 줄간격은 본문 크기의 1.5배 이상으로 시작한다.
- 주요 버튼의 높이는 56px 이상, 보조 버튼은 48px 이상으로 한다.
- 핵심 카드와 버튼 사이 간격은 12px 이상으로 두고, 밀집한 가로 버튼 나열을 피한다.
- 화면 첫 진입 시 페이지 제목을 읽고, 키보드 탭 순서는 ‘다음 행동 → 오늘 일정 → 도움 → 설정’ 순서를 따른다.
- 텍스트 확대 200%에서 가로 스크롤 없이 핵심 행동을 완료할 수 있어야 한다.
- 자동 전환·강한 scale 애니메이션을 사용하지 않으며 `prefers-reduced-motion`을 준수한다.
- 음성 입력은 보조 수단이며, 모든 기능은 터치·키보드만으로도 완료 가능해야 한다.

### 상태와 예외

| 상태 | 화면 처리 |
| --- | --- |
| 다음 일정 있음 | 목적지, 시각, 남은 시간, 길찾기 CTA를 표시한다. |
| 다음 일정 없음 | 일정 종료를 명확히 알리고 오늘 일정/홈으로 돌아가기 CTA를 제공한다. |
| 위치 권한 거부 | 권한이 필요한 이유와 설정에서 다시 허용하는 방법, 수동 장소 검색을 제공한다. |
| 경로 계산 실패 | 원인을 쉬운 문장으로 알리고 재시도·다른 이동수단·일정 보기 대안을 제공한다. |
| 오프라인 | 마지막으로 확인한 일정 시각을 표시하고, 지도/경로 기능의 제한을 설명한다. |
| 일정 변경됨 | 변경된 항목과 이유를 상단 알림으로 명확히 표시하며 되돌리기 가능 여부를 안내한다. |

### 검증 과업

1. 사용자가 ‘다음 장소까지 어떻게 가는지’를 10초 안에 찾을 수 있는지 확인한다.
2. 위치 권한을 거부한 상태에서 수동으로 목적지를 찾을 수 있는지 확인한다.
3. 글자 200%와 키보드만으로 길찾기 시작과 오늘 일정 확인을 완료하는지 검증한다.
4. 일정이 끝난 상태에서 사용자가 막히지 않고 홈 또는 전체 일정으로 이동하는지 확인한다.

### 기획 확인 필요

- `도움이 필요해요`가 안내 재정리인지, 가족/보호자 연결인지, 고객센터 연결인지
- 시니어 모드의 사용자 직접 선택과 동행자에 의한 설정 권한
- 길찾기 음성 안내 제공 여부와 외부 지도 앱 연동 방식
- 위치·여행 일정·연락 관련 동의와 데이터 보관 정책
