현재 Figma Make에서 제작되어 있는 여행 서비스 프로토타입을
아래 요구사항을 기준으로 전체적으로 수정하고 완성하라.

중요:

이 프롬프트는 이전 수정사항이 하나도 적용되지 않은 현재 프로젝트에서도
단독으로 실행할 수 있는 "전체 통합 수정 프롬프트"이다.

이전 차수의 프롬프트가 적용되어 있다고 가정하지 않는다.

아래의 서비스 구조, 화면, 기능, 데이터 흐름을 기준으로
현재 프로젝트 전체를 다시 정리하고 수정한다.

기존 디자인 중 좋은 부분은 유지하되
아래 요구사항과 충돌하는 구조는 수정한다.

단순히 화면을 추가하는 것이 아니라
화면 간 데이터와 상태가 연결되어
실제 여행 서비스처럼 동작하는 프로토타입을 만든다.

1. 서비스 핵심 콘셉트
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

이 서비스는 단순한 여행지 검색 앱이 아니다.

핵심 경험은 다음과 같다.

사용자가 YouTube에서 여행 콘텐츠를 발견한다.
↓
마음에 드는 여행 콘텐츠와 장소를 저장한다.
↓
저장한 여행지를 "내가 발견한 여행지"로 관리한다.
↓
AI가 저장한 여행 콘텐츠를 분석한다.
↓
사용자의 여행 취향을 파악한다.
↓
사용자가 AI 분석 결과를 확인하거나 수정한다.
↓
저장해둔 장소와 사용자의 취향을 기반으로 여행을 만든다.
↓
날짜 / 인원 / 이동수단 / 예산 / 동행자 조건을 설정한다.
↓
AI가 여행 일정을 만든다.
↓
숙소를 선택한다.
↓
필요하면 일정을 수정한다.
↓
출발 전 최종 확인을 한다.
↓
여행 중에는 현재 위치와 다음 장소를 안내한다.


핵심 메시지:

"내가 발견한 여행지를
AI가 나에게 맞는 여행으로 만들어준다."


서비스의 중심은
사진 검색이나 일반적인 장소 검색이 아니다.

YouTube에서 발견한 여행 콘텐츠와
그 콘텐츠를 통해 형성된 사용자의 여행 취향이
서비스의 핵심 데이터가 된다.

54. 최종적으로 반드시 지켜야 하는 원칙
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1.

홈 화면은 단순한 기능 메뉴가 아니라
사용자의 여행 상태를 보여주는 대시보드처럼 만든다.


2.

홈의 핵심은:

여행 계획하기
현재 내 여행 일정
내가 발견한 여행지
다가오는 여행
지난 여행


이다.


3.

YouTube 저장 여행지는
AI 취향 분석과 여행 계획의 핵심 데이터다.


4.

사진 검색은
서비스의 보조적인 장소 발견 기능이다.


5.

직접 검색도
보조적인 장소 발견 기능이다.


6.

날짜는 반드시
시작일 + 종료일을 선택한다.


7.

DAY 수는
선택한 날짜에 따라 자동 생성한다.


8.

DAY마다 실제 날짜가 연결된다.


9.

DAY 선택 시
일정과 지도 모두 변경된다.


10.

지도는 정적인 이미지가 아니라
현재 위치 / 선택 지역 / 장소 / 경로가 연결된
동적인 지도 UI로 구성한다.


11.

사진 분석 결과에 따라
지도 지역도 자동으로 변경한다.


12.

현재 위치와 여행지 마커를 구분한다.


13.

추천 장소와 추천 코스를
지도에서 확인할 수 있다.


14.

길찾기에서
현재 위치와 목적지가 실제 선택 상태와 연결된다.


15.

시니어 모드는
앱 전체에 적용한다.


16.

지난 여행마다
서로 다른 실제 여행 데이터를 사용한다.


17.

현재 여행이 있다면
홈에서 "현재 내 여행 일정"을 우선적으로 보여준다.


18.

사용자가 선택한 날짜와
홈 / 지도 / 일정 / 지난 여행 / 오늘의 여행의 날짜가
모두 동일한 데이터를 사용해야 한다.


19.

단순히 화면만 만들어놓지 말고
버튼 클릭 → 다음 화면 → 데이터 변경 → 결과 화면까지
전체 흐름을 연결한다.


20.

프로토타입이므로 실제 YouTube API,
실제 지도 API,
실제 GPS API가 연결되지 않은 경우에도
mock 데이터를 사용하여
마치 실제 서비스처럼 상태가 변화하도록 구현한다.


최종 목표는

"여행지를 검색하는 앱"

처럼 보이는 것이 아니라

"YouTube에서 내가 발견한 여행지를
AI가 이해하고,
현재 여행 상태까지 관리하면서
나에게 맞는 실제 여행으로 만들어주는 서비스"

처럼 보이는 것이다.
